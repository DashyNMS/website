Up and running in a few minutes

Nothing to install on your LibreNMS server. The MCP server runs alongside your AI app on your computer or server and queries LibreNMS over its API.

Pull the image

A 45 MB Docker container image for both Intel and ARM machines.

Create a read-only token

Generate an API token in LibreNMS for a read-only user so LibreNMS itself rejects write requests.

Add it to your app

Run one command for Claude Code, or add a few lines of config in Claude Desktop.

Step-by-step instructions are on the support page.

Ask in plain English.

Name a device by hostname, display name, IP address or LibreNMS ID. Every answer includes the supporting data.

Device health

Check state, uptime, open alerts, CPU, memory, fullest disk, and ports that are down or counting errors in one query.

Active and recent alerts

List open alerts or overnight activity. Inspect the matched rule, triggering values and recent flap history for any alert.

Trace an IP or MAC

Follow a MAC or IP address to its switch port with description, VLAN and link state. If multiple ports match, the server reports each candidate.

Events, logs and config diffs

Pull events, alerts and outages for any time range. Connect Unimus and Graylog to include config diffs and log entries from the same window.

Network overview

Summarise up and down devices, alerts by severity, busiest ports, error counters and hot sensors across the whole network or one site.

Inline LibreNMS graphs

Fetch any device, port or sensor graph directly into the chat, from the last hour to the last year.

Safe by design.

The server reads from your network without write tools and strips secrets before returning config text.

Read the privacy policy

Read-only tools

No tool modifies your network. Pair it with read-only tokens so LibreNMS, Unimus and Graylog reject writes too.

Secrets redacted first

The server strips passwords, SNMP communities and keys from config backups before sending them to the assistant.

Network text stays data

Port descriptions and log lines pass through as quoted data, not instructions.

Local tokens

The server reads tokens from your local config, never logs them, and sends each only to its own server.

More of DashyNMS.

Desktop, Mobile and MCP share the same LibreNMS, Unimus and Graylog engine, so health and alert counts match across all three.
